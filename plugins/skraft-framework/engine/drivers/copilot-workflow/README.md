# drivers/copilot-workflow

Copilot CLI dynamic workflow driver `skraft-pipeline`: composes Init and RunPipeline with the Node adapters; decides nothing.
Imports use cases, ports and infrastructure; never another driver.

- `register.mjs`: `register({ defineWorkflow, joinSession, … })`, called by the extension entry, the only file that imports the SDK. Builds the workflow and the tool each in its own `try`; a join the host refuses is tried again without the tool; each failure goes to `session.log` at level `error` with a fixed message, once joined. Nothing is written to stdout.
- `session-dir.mjs`: the session's working directory, live: seeded from `session.rpc.metadata.snapshot()` once joined, then moved by each `session.context_changed` (`onEvent`, registered before the join RPC); an absolute path only, null while unknown. A run reads it when it starts (refused `no-directory` while null), `skraft_decide` on each call. No driver reads `process.cwd()`.
- `skraft-pipeline-workflow.mjs`: `SKRAFT_PIPELINE_META` and the workflow body (slug → Init then RunPipeline; no slug → the active pipeline). The host gives the home folder whose `.skraft/config.json` is read (`homedir()` in the extension; a folder of their own in the tests, never the machine's).
- `cancellation.mjs`: `isCancellation(error, signal)`: the run's signal aborted, or an `AbortError`. The workflow returns an outcome for every other failure (`{ status: 'error', code: 'unexpected', reason: <fixed> }`, every key present) and rethrows a cancellation; `ctx-agent-runner.mjs` rethrows a cancelled `ctx.agent` instead of reporting an agent failure. A caller gates on a `completed` run whose `outcome.status` is the one it expects.
- `ctx-agent-runner.mjs`: AgentRunner on `ctx.agent`; resolves the session agent id (`agentIds` arg, session list, else `<plugin>:<id>` for a plugin agent and the bare id for a repository one); `runMany` calls `ctx.agent` for the whole batch at once, Copilot bounding it by `maxConcurrentSubagents`. A dispatch carries the Copilot models the configuration gives its family (`models` of the four layers, the preferred first) and its Copilot effort; the model goes in the `model` option, the effort in `reasoningEffort`, and with no model the agent runs on the session's. No model name is written in code and no workflow argument chooses one. `refusalOf` reads a thrown error: a refused effort is asked again on the same model without it (label suffixed ` · without effort`), a refused model moves to the next name (` · <name>`), then to the session's model (` · session model`), with the same effort; any other failure is the answer. The refusal texts are assumed until the host probe's `copilot-model-refusal` and `copilot-effort-refusal` checks (`--agent-calls`) record them in `docs/v2/host-verification.md`. The answer names the model it ran on, null for the session's.
- `ctx-progress.mjs`: PipelineProgress on `ctx.log`.
- `ctx-human.mjs`: HumanInteraction: the question in the log, then `ctx.pause(key)`; a resumed run whose question is still open gets no answer and waits.
- `skraft-decide-tool.mjs`: the `skraft_decide` tool, through Decide (`key`, `answer`, `reason` for a refusal).

The SDK entry is `com.github.copilot/extensions/skraft-pipeline/extension.mjs`.
Tested in integration against a simulated `ctx` (`tests/skraft-framework/integration/copilot-workflow/`).
