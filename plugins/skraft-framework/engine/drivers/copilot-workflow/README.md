# drivers/copilot-workflow

Copilot CLI dynamic workflow driver `skraft-pipeline`: composes Init and RunPipeline with the Node adapters; decides nothing.
Imports use cases, ports and infrastructure; never another driver.

- `register.mjs`: `register({ defineWorkflow, joinSession, createCanvas, CanvasError, … })`, called by the extension entry, the only file that imports the SDK (as a namespace: an SDK without `createCanvas` leaves the canvas out, logged). Builds the workflows, the tool and the canvas each in its own `try`; a join the host refuses is tried again without the canvas, then without the tool, then without both, never without the workflows; each failure goes to `session.log` at level `error` with a fixed message, once joined. Nothing is written to stdout and nothing starts at import.
- `session-dir.mjs`: the session's working directory, live: seeded from `session.rpc.metadata.snapshot()` once joined, then moved by each `session.context_changed` (`onEvent`, registered before the join RPC); an absolute path only, null while unknown. A run reads it when it starts (refused `no-directory` while null), `skraft_decide` on each call. No driver reads `process.cwd()`.
- `skraft-pipeline-workflow.mjs`: `SKRAFT_PIPELINE_META` and the workflow body (slug → Init then RunPipeline; no slug → the active pipeline). The host gives the home folder whose `.skraft/config.json` is read (`homedir()` in the extension; a folder of their own in the tests, never the machine's).
- `cancellation.mjs`: `isCancellation(signal)`: the run's signal is aborted (an `AbortError` alone is the failure of what threw it). The workflow returns an outcome for every other failure (`{ status: 'error', code: 'unexpected', reason: <fixed> }`, every key present) and rethrows a cancellation; `ctx-agent-runner.mjs` rethrows a cancelled `ctx.agent` instead of reporting an agent failure. A caller gates on a `completed` run whose `outcome.status` is the one it expects.
- `workflow-args.mjs`: `readArgs(ctx)`: the arguments are model-written and the host does not enforce `argsSchema`; a key the workflow does not declare is refused (`invalid-args`), and so is an `agentIds` entry that does not name, by id or name, a session agent the session lists for that same agent file id (`invalid-agent-ids`); a refusal starts nothing and never echoes what it refused.
- `ctx-agent-runner.mjs`: AgentRunner on `ctx.agent`; resolves the session agent id (`agentIds` arg once `readArgs` accepted it, session list, else `<plugin>:<id>` for a plugin agent and the bare id for a repository one); `runMany` calls `ctx.agent` for the whole batch at once, Copilot bounding it by `maxConcurrentSubagents`. A dispatch carries the Copilot models the configuration gives its family (`models` of the four layers, the preferred first) and its Copilot effort; the model goes in the `model` option, the effort in `reasoningEffort`, and with no model the agent runs on the session's. No model name is written in code and no workflow argument chooses one. `refusalOf` reads a thrown error: a refused effort is asked again on the same model without it (label suffixed ` · without effort`), a refused model moves to the next name (` · <name>`), then to the session's model (` · session model`), with the same effort; any other failure is the answer. The refusal texts are assumed until the host probe's `copilot-model-refusal` and `copilot-effort-refusal` checks (`--agent-calls`) record them in `docs/v2/host-verification.md`. The answer names the model it ran on, null for the session's. A failed call is said by what Copilot refused (`Copilot refused the model`, `… the reasoning effort`, else `the Copilot agent call failed`), never by the error's text.
- `ctx-progress.mjs`: PipelineProgress on `ctx.log`.
- `ctx-human.mjs`: HumanInteraction: each question is put to the person once, during the run, in Copilot's own dialog (`host-question.mjs`); what they give is the answer, journaled with the dialog's provenance (`host-confirmed`). When Copilot cannot put it (no elicitation, `autopilot`, mode unknown, rate limit, a dialog it never showed) or the person dismisses it, the log says why and how to answer (resume to be asked again, ask Copilot in the chat, or `skraft decide` in a terminal), naming no tool, then `ctx.pause(key)`; resumed, the run puts the question again.
- `host-question.mjs`: `askInHost(dialog, question)`: a question with options as a choice among them (`session.ui.select`), a blocked step's as a text field for the instruction or STOP (`session.ui.input`); a refusal chosen (`REJECTED`) asks its reason next, in a text field. No confirmation after the answer: the value the dialog gives is the decision. Measured: probe checks `select-joined-session-from-workflow` and `input-joined-session-from-workflow`, Copilot CLI 1.0.102-1.
- `skraft-decide-tool.mjs`: the `skraft_decide` tool takes no argument (any key refused, never echoed): neither the question nor the answer comes from the model. It reads the question the active pipeline waits on (Observe, in the session's directory at the time of the call), puts it to the person once through `host-question.mjs`, as the run does, and records what they give through Decide with the dialog's provenance; no confirmation after it. For the chat, when the run could not put its question; then the run is resumed.
- `host-confirmation.mjs`: Copilot's own dialog: `ask` (yes or no, `session.ui.confirm`, the review consent), `choose` (one of the options, `session.ui.select`), `write` (a text, `session.ui.input`); the value it gives is the answer, journaled `by: 'host-confirmed'`. Refused without elicitation, in `autopilot`, when `rpc.mode.get` does not answer a mode within 5 s, and past 5 requests per 10 min in the process (a `not-asked` gives its place back). A no, a dismissed dialog or no answer within 2 min is `not-answered`; a throw or any other result is a dialog the host never put, `not-asked`. Decide refuses (`unknown-provenance`) a provenance not in the domain's `HUMAN_PROVENANCES`.

- `pipeline-canvas.mjs`: the `skraft-pipeline` canvas, built from the SDK's `createCanvas` and `CanvasError`. No input (a slug or any key is refused): it shows the active pipeline (`.active-slug`) of the session's directory, read on each open, action and refresh, never a guessed slug. Each open instance gets its own loopback server, started by `open` (Copilot CLI 1.0.102-1 calls `open` again for an open instance: the same panel is returned), stopped by `onClose`; at most 4 at once: past that, `open` closes the oldest panel no page listens to, and refuses only when a page listens to each. It takes no answer: its one action, `get_pipeline`, is read-only, and its page has no answer form nor route; Copilot puts each question to the person in the chat. Every refusal or failure is a CanvasError with a fixed text.
- `canvas-content.mjs`: what the page draws, from Observe: each phase with its workflow steps (the step under way is the open one; outcome, pass), the reviews' last passes, each component's last gate results (never a command or evidence), the labelled edges taken, and the question with where to answer it (the Copilot chat, or `skraft decide` in a terminal). No cost: Copilot reports credits, not USD. A session with no directory, or a pipeline that cannot be read, gets fixed content, never exception text.
- `canvas-server.mjs`: the panel's server on 127.0.0.1: a Host that is not its own address is refused (421); a per-panel token travels only in the url `open` gives the host (`/?t=<token>`), never in the page: the page and the event stream need it, compared by SHA-256 digest in constant time; it serves the page, its script, its stylesheet and the stream, nothing else (no answer route); `default-src 'none'` CSP; the content is read again every second while a page listens and sent when it changed. Threat model: `docs/v2/host-verification.md` (« Canvas `skraft-pipeline` : modèle de menace et cadre »). `canvas-ui/` holds the page, its script and its stylesheet: static assets the server serves, which set every text with `textContent` and decide nothing.

The SDK entry is `com.github.copilot/extensions/skraft-pipeline/extension.mjs`.
Tested in integration against a simulated `ctx` (`tests/skraft-framework/integration/copilot-workflow/`); the canvas on a simulated canvas host, its server over real HTTP (`tests/skraft-framework/integration/pipeline-canvas/`).
