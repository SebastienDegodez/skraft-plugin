# Install skraft on a host

Install the `skraft` plugin on your host, and get the `skraft` command line answering from your
repository.

## Prerequisites

- Node 22 or later, and Git.
- A host: Claude Code, GitHub Copilot CLI, or VS Code with GitHub Copilot.
- `gh` signed in, only to read a story's issue or open the pull request
  ([Hosts](../reference/hosts.md#prerequisites)).

## 1. Install the plugin

The `SebastienDegodez/skraft-plugin` repository is a marketplace named `skraft`; the pipeline's
plugin in it is also called `skraft`.

<Tabs groupId="host" queryString="host">
<TabItem value="claude-code" label="Claude Code" default>

Type in the conversation, not in a terminal:

```console title="Claude Code"
> /plugin marketplace add SebastienDegodez/skraft-plugin
> /plugin install skraft
```

Open `/plugin`: `skraft` is among the installed plugins.

Claude Code.
:::

</TabItem>
<TabItem value="copilot-cli" label="GitHub Copilot CLI">

In a terminal:

```console
$ copilot plugin marketplace add SebastienDegodez/skraft-plugin
$ copilot plugin install skraft@skraft
```

In a Copilot session, the same commands read `/plugin marketplace add …` and
`/plugin install skraft@skraft`. Check with `copilot plugin list`: `skraft` is listed.

:::note[Screenshot pending a real run]
A capture of `copilot plugin install` replaces the block above after a real run in Copilot CLI.
:::

To work on a clone of the plugin, install it from its local folder:
`copilot plugin install ./plugins/skraft-framework`.

</TabItem>
<TabItem value="vscode" label="VS Code">

1. In `settings.json`, enable agent plugins and add the marketplace:

   ```json
   "chat.plugins.enabled": true,
   "chat.plugins.marketplaces": ["SebastienDegodez/skraft-plugin"]
   ```

2. Run **Chat: Open Customizations**, **Browse** tab, search for `skraft`, then **Install**.
   You can also search for `@agentPlugins` in the Extensions view.
3. For a local clone, declare its folder instead of installing:

   ```json
   "chat.pluginLocations": { "<clone path>/plugins/skraft-framework": true }
   ```

   In JSON, double each backslash of a native Windows path:
   `"C:\\src\\skraft-plugin\\plugins\\skraft-framework": true`.

In **Chat: Open Customizations**, **Plugins** section, `skraft` is listed and enabled.

## 3. Make the `skraft` command available {/* #skraft-command */}

Install the command once per machine, under sh as under PowerShell (Node 22 or later):

```console
$ npm i -g @skraft/cli
```

npm puts `skraft` in its global folder, which is already in your PATH (with a `skraft.cmd` on
Windows). The package holds no engine: at each call, `skraft` finds the plugin your host
installed and runs its engine ([lookup order](../reference/cli-maintenance.md#skraft-command)). A plugin
update by the host is followed at the next call. `skraft upgrade` updates both the command and
the plugin in each host.

From the root of your repository:

```console
$ skraft --version
```

You see the plugin's version, for instance `2.0.0-alpha.19`, and on stderr the host and folder
that answered (`plugin: copilot …`). The other guides write `skraft <command>` for this command.

Then run `skraft doctor`. In a repository not configured yet:

```text
ok    node: Node v22.…
FAIL  config: no skraft-config.json; run skraft init to detect the components
ok    vscode: …
skraft doctor: 1 checks failed
```

The `FAIL` on `config` is expected: it goes away once the components are detected
([Configure the components](./configure-components.md)). Under
VS Code, the `vscode` line says which driver will run the pipeline: the Copilot SDK
(`engine/drivers/copilot-sdk/skraft-run.mjs`) when it is found, else the orchestrator agent that
conducts `skraft next` and `skraft record`.

## 4. Check that the host sees skraft

<Tabs groupId="host" queryString="host">
<TabItem value="claude-code" label="Claude Code" default>

Type `/skraft` in the conversation: the **Skraft** pane opens and shows `skraft — idle`.

</TabItem>
<TabItem value="copilot-cli" label="GitHub Copilot CLI">

- `/agent` in a session: `skraft:skraft-orchestrator` is in the list.
- `/skraft` in a session: the command answers and starts no run: it opens the run view, or tells
  you to type `skraft status`.

</TabItem>
<TabItem value="vscode" label="VS Code">

- The chat's agent picker: skraft's orchestrator agent is in the list.
- `/skraft` in the chat: not measured yet.

</TabItem>
</Tabs>

Copilot exposes the command as `/skraft`, without a prefix (measured on Copilot CLI 1.0.105). If
`/skraft` is missing, check the plugin list and open a new session.

## Troubleshooting

### Windows: `/plugin marketplace add` fails on a path that is too long

Clone the repository to a short path
(`git clone https://github.com/SebastienDegodez/skraft-plugin C:\s\skraft`), then
`/plugin marketplace add C:\s\skraft` and `/plugin install skraft`.

### `node: Node v20…; skraft needs Node 22 or later`

Install Node 22 or later, then run again.

### Copilot CLI: `skraft:skraft-orchestrator` missing

Check `copilot plugin list`, then open a new session; a run refused for that reason carries the
code `agent-unavailable`.

### `skraft: command not found` after `npm i -g @skraft/cli`

Open a new terminal; `npm prefix -g` shows the folder npm installs into, which must be in your PATH.

### `skraft: the skraft plugin was not found in GitHub Copilot CLI nor in Claude Code`

Install the plugin in a host (step 1), or set `SKRAFT_PLUGIN_ROOT` to the plugin folder, for
instance a clone.

### `skraft` runs the wrong plugin

`skraft --version` names the host and folder it used. Set `SKRAFT_PLUGIN_ROOT` to choose another
one.

### You ran `skraft install` with an earlier version

Remove `~/.skraft/bin` (and its line in your shell profile, or from your user PATH on Windows),
then install the package.
