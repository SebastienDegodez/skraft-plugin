# Répondre à une question du run

Donnez la décision humaine qu'un run attend, pour qu'il reparte.

Un run qui pose une question **attend** : il ne fait plus rien tant que personne n'a répondu, et
le relancer repose la même question, sans relancer d'agent.

## Prérequis

- Un run au statut `waiting` (`skraft status`, ou le panneau **Skraft**).
- Pour la ligne de commande : un terminal interactif à la racine de la copie de travail ;
  `skraft` est la commande que [`npm i -g @skraft/cli`](./install-on-a-host.mdx#skraft-command) met en place ; la ligne longue `node "<dossier du plugin>/engine/drivers/cli/skraft.mjs"` marche sans elle.

## 1. Lire la question et sa clé

```console
$ skraft status
```

```text
skraft checkout: waiting
…
question: adr-ratification (adr)
answer: skraft decide adr-1 RATIFIED|REJECTED (--reason <text> with REJECTED)
Ratify the Proposed ADRs docs/adr/adr-001-card-provider.md? RATIFIED marks them Accepted; REJECTED sends DESIGN back with your reason.
```

La ligne `answer:` donne la clé (`adr-1`) et les réponses permises :

| Question | Réponses | Raison obligatoire |
|---|---|---|
| `adr-ratification` | `RATIFIED`, `REJECTED` | avec `REJECTED` |
| `scenario-review` (en-tête `Scenarios`) | `APPROVED`, `REVISE` | avec `REVISE` : vos corrections, envoyées à DISTILL |
| `review-consent` (`skraft review --pr --publish`, en-tête `PR comment`) | `ACCEPTED`, `DECLINED` | — |
| `environment` | `RETRY` (après avoir réparé la machine ou `skraft-config.json`), `ABORT` | — |
| `mutation-plan` | `APPLY`, une consigne à vous, ou `STOP` | — |
| `blocked` | une consigne pour l'agent, ou `STOP` | — |

Ce que chaque réponse déclenche : [Questions à un humain](../reference/run-journal.md#human-questions).

Une question `environment`, `blocked` ou `review-ceiling` finit par
`The run so far (commits, refusals, incidents): <dossier de suivi>/run-report.md`. Ouvrez ce
fichier : `## Waiting on` cite la question et la ligne `skraft decide` exacte ; `## Commits`,
`## Refusals` et `## Incidents` montrent ce que le run a fait avant de s'arrêter
([Rapport du run](../reference/run-journal.md#run-report)).

Une question `environment` dit qui corrige sur sa ligne `Cause:`, et où la commande en échec a
écrit sur sa ligne `Output:` :

| `Cause:` commence par | À corriger avant `RETRY` |
|---|---|
| `the machine` | installer ou démarrer le programme ou le service, accorder la permission ou corriger le hook Git ; le log `Output:` dit lequel |
| `skraft-config.json` | changer la commande ou le chemin que nomme la première ligne ([Configurer les composants](./configure-components.md)) |
| `what the replay judge read` | lire la réponse du juge que nomme la ligne `Output:` (`logs/judge-<sha court>-<red\|green>.md`) : sa note dit ce que montrent les logs et quoi corriger sur la machine (un programme, un runtime de conteneurs, un identifiant) |

`RETRY` relance l'étape là où elle s'est arrêtée et ne consomme aucune tentative de l'agent ;
après une question du juge, il rejoue le commit et réinterroge le juge.

## 2. Répondre depuis votre hôte

<Tabs groupId="host" queryString="host">
<TabItem value="claude-code" label="Claude Code" default>

1. Choisissez une option dans la boîte de dialogue que le mod ouvre (en-tête `ADR`,
   `Pull request`, `Environment`…).
2. Pour un refus (`REJECTED`, `REVISE`), une deuxième boîte demande la raison : tapez-la sous **Other**.
3. Pour une question `blocked` ou `mutation-plan`, tapez votre consigne sous **Other**, ou
   choisissez `STOP` (`APPLY`).

Boîte fermée, le run attend. Répondez plus tard par un bouton du panneau **Skraft**, ou dans la
conversation :

```console title="Claude Code"
> /skraft decide adr-1 REJECTED prendre le prestataire déjà sous contrat
```

Les mots après la réponse forment la raison ; pour une question `blocked`, tous les mots après la
clé forment la consigne. `/skraft decide` enregistre la réponse, puis reprend le run.

Claude Code dessine la boîte de dialogue ainsi ; **Type something.** est le champ **Other** :

```text title="Claude Code"
☐ ADR

Ratify the Proposed ADRs docs/adr/adr-001-card-provider.md? RATIFIED marks them Accepted;
REJECTED sends DESIGN back with your reason.

❯ 1. RATIFIED
  2. REJECTED
  3. Type something.
─────────────────────────────────────────────────────────────
  4. Chat about this

Enter to select · ↑/↓ to navigate · Esc to cancel
```

</TabItem>
<TabItem value="copilot-cli" label="GitHub Copilot CLI">

1. Le workflow écrit la question exacte en attente et se met en pause. Demandez à Copilot de la
   présenter via l'outil natif proposé `ask_user` ou `askQuestions` : choisissez une option,
   ou tapez votre consigne.
2. Pour un refus (`REJECTED`, `REVISE`), tapez la raison dans le champ qui suit.

Copilot lit `skraft_decide {}` sans poser de question ni enregistrer, puis relaie uniquement
votre réponse native avec `skraft_decide {key, answer, reason?}`. Aucune seconde confirmation.
Après `Recorded: …`, Copilot reprend le MÊME ID de run du workflow ; si cet ID est absent,
reprenez ce run en pause depuis `/workflows`, pas un nouveau workflow.

`/skraft decide [<clé>] <réponse>` agit ici autrement que sous Claude Code : elle n'enregistre rien des mots
tapés. L'outil natif de question fournit la réponse.
Si l'outil est absent ou que vous fermez la question, Copilot signale ce blocage, laisse le run
en pause et n'enregistre rien ; une réponse en prose ordinaire ne le remplace pas.

Le canvas `skraft-pipeline` montre la question mais ne prend aucune réponse.
Cette voie couvre uniquement les questions du pipeline ; la publication REVIEW demande
toujours une confirmation explicite de l'hôte, pas une réponse relayée par le modèle.

</TabItem>
<TabItem value="vscode" label="VS Code ou terminal">

Dans la boucle MCP de VS Code, l'orchestrateur lit `skraft_status`, pose la question exacte
et ses options via l'outil natif proposé `ask_user` ou `askQuestions`, puis relaie votre réponse
avec `skraft_answer {key, answer, reason?, workspace}`. Une raison de refus vient du même
outil natif. Un enregistrement réussi continue par `skraft_next` dans le même espace de travail.
Outil natif absent ou question fermée : blocage concret, run en pause, aucun enregistrement.

La voie terminal autonome garde son consentement interactif :

```console
$ skraft decide adr-1 REJECTED --reason "prendre le prestataire déjà sous contrat"
```

Le terminal demande `skraft decide: record REJECTED for adr-1? [y/N]` : tapez `y`. Pour une
question `blocked`, la consigne va entre guillemets : `skraft decide design-1 "utiliser la
passerelle bancaire"`. Puis reprenez le run : `skraft-run.mjs` de nouveau (SDK Copilot), ou
demandez à l'agent orchestrateur de relancer `skraft next`.

</TabItem>

## 3. Vérifier que le run est reparti

```console
$ skraft status
```

Le statut n'est plus `waiting`. `skraft report` liste chaque réponse donnée, avec la façon dont
elle a été enregistrée (`host`, `decide`, `host-confirmed`, `cli-tty`).

## Ce que devient un refus

- **`REJECTED` sur un ADR** : l'architecte repasse DESIGN avec votre raison. Au-delà de 3
  rejets, le run pose la question `blocked` sur `design` : une consigne relance l'architecte,
  `STOP` termine le run (`loop-ceiling`).
- **`REVISE` sur les scénarios** : le concepteur d'acceptation repasse DISTILL avec vos
  corrections, puis sa revue et la question reviennent. Corrigez d'abord vous-même le `.feature`
  ou le test si vous le souhaitez, et dites-le dans la raison. Au-delà de 2 révisions, le run pose
  la question `blocked` sur `distill`.
- **`DECLINED` sur un consentement** : la réponse est écrite dans `skraft-config.json`
  (`publish.pullRequest` ou `publish.visuals`) et n'est plus redemandée ; le run continue en
  local ([Publier la pull request d'un run](./publish-pull-request.md)).
- **`review-consent`** : la réponse (`ACCEPTED` ou `DECLINED`) est gardée une fois par dépôt dans
  votre propre `~/.skraft/config.json` (`reviewComments`), pas dans `skraft-config.json` ; un
  `DECLINED` laisse le commentaire de revue hors de la pull request.
- **`ABORT`** : le run se termine `blocked` (code `environment`) ; démarrez un nouveau slug une
  fois la machine réparée.
- **`STOP`** : le run se termine `blocked`, définitivement pour ce slug.

## Dépannage

Une réponse refusée n'enregistre rien ; le run attend toujours.

| Message | Action |
|---|---|
| `no question adr-2; waiting: adr-1` | Reprendre la clé que le message nomme. |
| `adr-1 was already answered RATIFIED` | Rien à faire : reprendre le run. |
| `REJECTED needs the reason, which goes back to the agent` | Ajouter `--reason "…"`. |
| `the answer must be one of RATIFIED, REJECTED` | Écrire une des options. |
| `skraft decide records a person's answer: run it yourself in an interactive terminal of your own, not an agent's shell; nothing was recorded` | Lancer la commande vous-même, dans un terminal interactif. |
| `Refused: …; nothing was recorded.` (Copilot) | Corriger la clé, l'option ou la raison requise ; relayer de nouveau la réponse native, puis reprendre le même run. |
| `not recorded — no active pipeline in this working copy` (Claude Code), alors que `skraft status` montre le run en attente | Répondre par `skraft decide <clé> …` dans un terminal, puis `/skraft <slug>` dans Claude Code. |
| Vous avez écrit la réponse dans la conversation au lieu de la boîte de dialogue | Ce n'est pas une réponse : le run attend toujours. Utiliser `/skraft decide`. |
