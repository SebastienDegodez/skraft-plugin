# ADR-009 — Hooks ship from one canonical manifest and a generated Copilot copy

**Status:** Proposed
**Date:** 2026-09-24
**Supersedes:** ADR-008

## Context

This supersedes ADR-008, which prescribed that no hook manifest ships under
`com.github.copilot/hooks/`. Measured against Copilot CLI 1.0.80, the CLI read
`<plugin-root>/hooks/hooks.json` and nothing else, and a hand-kept second manifest had already
drifted by one token and silently disabled every hook on VS Code for a week.

On 2026-09-17 the two-editable-agent-trees refactor put a manifest back under
`com.github.copilot/hooks/`, generated from the canonical one. ADR-008's first consequence no
longer describes what ships. Measured since:

- Copilot CLI 1.0.83 fixture tests passed namespaced agent discovery, `SessionStart` and
  `PreToolUse` with `CLAUDE_PLUGIN_ROOT`, paths with spaces included.
- `scripts/copilot-hook-smoke.mjs`, CLI 1.0.83 pinned, isolated `COPILOT_HOME`: the allowed and
  the denied probe each recorded exactly one hook audit entry, and the forbidden write was
  refused. One entry per probe means the CLI registered the hooks once, not once per file.
- Which of the two files Copilot CLI 1.0.83 loads was not isolated.

ADR-008's forces still hold: a hook that never spawns is silent, schema validation cannot see
it, and hook discovery is undocumented and can move in any release.

## Decision

**Author hooks in one file, `plugins/skraft-framework/hooks/hooks.json` (Claude schema,
`${CLAUDE_PLUGIN_ROOT}`). Ship a byte-exact copy at `com.github.copilot/hooks/hooks.json`.
Declare no `hooks` pointer in any manifest.**

1. The copy is generated, never edited: `npm run plugin:build` writes it from the canonical
   file, and `npm run plugin:check`, run in CI, fails when the copy differs or when any other
   file sits beside it. The token drift ADR-008 recorded cannot reach a generated byte copy.
2. No manifest names either file. On the Claude-family harnesses, which load
   `hooks/hooks.json` on their own, a pointer is a second registration.
3. The wiring is verified by execution: `scripts/copilot-hook-smoke.mjs` and
   `scripts/claude-plugin-smoke.mjs` assert on a real session's audit log and on a refused
   write. They are rerun after any change to the hook manifest or the plugin layout.

## Consequences

**Positive**

- One authored manifest; the copy's parity is a CI check, not a review duty.
- The measured Copilot session registers the guards once.

**Negative**

- Two physical files depend on undocumented discovery rules. A harness that loads both would
  evaluate every guard twice and write every audit line twice; only a live run shows it.
- Live discovery on Codex and VS Code remains unverified.

**Neutral**

- ADR-008 remains the record of what Copilot CLI 1.0.80 did.
- `.github/hooks/skraft-framework.json`, the repository-level registration for a checkout of
  this repository, is out of scope.
